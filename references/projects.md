### 业务不变量

- 客户、品牌、门店范围明确；品牌级资料只有明确共享时才进入门店，不自动跨品牌继承。
- 对外引用只使用当前范围内可公开、已确认、有效且无冲突的事实；研究模式的原始资料不能直接视为可发布事实。
- 套餐价格、人数、包间容量、房型等精确条件以结构化数据为依据；模糊描述检索不能覆盖这些硬条件。
- SQL 由受限查询计划生成参数化只读查询，并执行范围检查；不执行模型任意 SQL。
- 事实可追溯原始资料，修订有历史；来源归档后的关联事实不得继续作为当前可用证据。
- 无资料、未配置模型、引用不合法等情况如实呈现；不能编造酒店信息。

### 已发生问题转为回归案例

| 场景 | 需要验证的结果 |
|---|---|
| 负价格、小数人数、非法日期、容量矛盾 | 客户端提示且服务端拒绝不合法数据；合法边界依字段规则测试 |
| 损坏文件改名 .jpg | 检查真实文件内容，不只看扩展名；失败不残留可用图片记录 |
| 图片说明过长 | 明确限额或完整保存，不静默截断 |
| 上传中切换档案、多个保存请求乱序 | 响应不能写入新选中的档案，也不能覆盖较新修改 |
| 保存失败后重试/刷新 | 保留或可恢复未保存输入；成功与失败提示符合真实状态 |
| 下载档案 ZIP | 浏览器拿到文件、能解压、内容与正确档案匹配；接口通过不代表下载交互已验收 |
| 公网文案 | 不把服务器保存描述为“保存在本机” |

历史验收有浏览器选图被扩展权限阻断、下载捕获超时的未验证项。将它们作为需重新核实的候选，不声称仍被阻断或已经解决。

本地文档指出共用/本地访问模式不等同于完整多租户身份系统。验收须区分数据范围过滤与用户身份隔离，不夸大安全能力。
备份 SQLite 时连同附件使用一致性备份方式；不能随意复制正在写入的主数据库并忽略 WAL。

### 业务不变量与回归案例

| 场景 | 需要验证的结果 |
|---|---|
| 未经人工校对 | 标为“AI 自动判定”，不可显示为人工确认 |
| 顾问/客户角色存疑 | 提醒核实，可提供概览；暂停依赖角色的意向分、相关评分及小记差异 |
| 顾问说出营销承诺 | 不能将顾问的话误算为客户需求、意向或承诺 |
| 人工修改文字或角色 | 旧分析标识待更新；重新分析后同步相关结果和对应日期日报 |
| 默认只显示前 10 句 | 折叠不裁掉后续保存/分析内容；无需滚动全文也能保存 |
| 凌晨批处理 | 按 Asia/Shanghai 测时间边界；2 点之后上传归下一批，立即处理另有明确入口 |
| 历史录音补传 | 按通话发生时间关联小记和日报，而非简单使用上传日 |
| 重复上传、重复点击、调度与立即处理并发 | 同一业务任务不重复分析/扣费，或按明确的版本与重算规则计费 |
| 中断、模型超时、服务重启 | 状态可恢复，失败不伪装成功，重试遵循任务身份与计费规则 |
| 分配、放弃、公海领取、超时回收 | 作为系统流转记录展示，不计为有效人工跟进，不自动延长公海期限 |
| 小记与 AI 分析不一致 | 保留销售小记原文，AI 提示差异，不擅自覆盖业务记录 |
| 搜索关键词 | 历史需求为 15 字上限；按当前规范核对粘贴与中文边界，不对其他输入套用 |

UI 以“上传、等待/立即处理、看结果、必要时校对”为主，尽量减少多套入口与矛盾状态。预计积分和实际用量须清楚区分。
使用虚构客户、短合成转写和模拟时间测试；未经当前授权不拨号、不发送消息、不将真实录音交给新服务。
