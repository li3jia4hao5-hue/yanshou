# UI 设计与真实视觉验收

## 设计先于全面实现

先确定用户主要工作：酒店建档人员填写和查找资料；婚恋销售上传录音、看分析、维护客户。以当前任务和已确认需求为准，避免把运营后台设计成营销落地页。

优先使用用户认可的截图、现有组件与品牌资产。尚无方向的大改版，先做两个差异清晰的关键页面预览供选择；已经指定方向或要求自主完成则直接采用并说明。小修不强制出两套方案。

记录足够实施的设计规范：主色/中性色/状态色、中文字体与字号层级、间距、页面密度、按钮与表单、列表/详情布局。不要把某个配色、卡片或字体当成所有项目的固定审美。可用的 UI UX Pro Max 可辅助选择，未安装时本流程仍可执行。

## 操作层级

- 页面首先回答：我在哪个客户/品牌/门店？任务处于什么状态？下一步能做什么？
- 每个主要任务区域突出一个主动作；重试、重新分析、删除等按使用频率和后果安排，不堆相似按钮。
- 常规用户看到业务语言；模型参数、原始 JSON、完整日志放入适当的详情或管理员区域。
- 长文字/转写支持摘要或折叠，主操作在折叠状态下可达。折叠只影响显示，不改变存储和分析输入。
- 区分保存中、保存成功、失败、待处理、处理中、需核实；没有回执前不显示已完成。
- 草稿、AI 自动判定、人工校对、结果已过期应有清楚文字标记，不只依赖颜色。

## 视觉验收

在可用的真实浏览器中运行当前版本，检查目标设备尺寸；至少覆盖项目主要桌面尺寸，涉及移动使用时增加窄屏。尺寸由项目决定，不把全部分辨率列为固定必测。

用真实长度的中文标题、列表、状态、空值和长文件名验证：层级、留白、对齐、文字可读性、溢出、对比度、键盘焦点、弹窗滚动、主要按钮可达性。查看实际截图后再修正，不仅阅读 CSS。

检查有数据、空数据、加载、失败和长内容状态。功能范围涉及表单时检查错误是否定位字段、是否保留用户输入，切换对象时是否防止迟到请求写错对象。
